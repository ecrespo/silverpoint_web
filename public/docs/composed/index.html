New in 0.7.0

Composed components

New in silverpoint 0.7.0 and reflex-silverpoint-react 0.7.0. Components drawn on silverpoint's frames and tones: tables, pagination, statistics, collapse panels, and overlays — modal, drawer, popover, tooltip, select, menu and toast — in React, Vue, Angular and Reflex.

Drawn with silverpoint's own pieces

@silverpoint/grounds/ui.css draws its hand-inked frames, hatched tones and heightening on any element that follows its markup contract, so these components are drawn with exactly the same pieces as the first 17. silverpoint 0.7.0 ships them in React, Vue and Angular, on @silverpoint/<framework>/ui/<name> beside the others (38 UI components in all); SpSurface and SpGlyph (sp_surface, sp_glyph) are the building blocks, for components of your own.

Mind this
The live demos are the Reflex versions of reflex-silverpoint-react 0.7.0. Their API differs in places: snake_case, an sp_trigger button, overlays on Radix primitives (the adapters use the native <dialog> and the Popover API), side="right" where the adapters say "end", and they do not read silverpoint_provider: pass ground, substrate, mode and palette explicitly.

import { useState } from 'react';
import { uiSortRows } from '@silverpoint/core/ui';
import { SpTable } from '@silverpoint/react/ui/table';

const columns = [
  { key: 'team', title: 'Team', sortable: true },
  { key: 'region', title: 'Region' },
  { key: 'load', title: 'Load %', align: 'end', sortable: true },
  { key: 'incidents', title: 'Incidents', align: 'end', sortable: true },
] as const;

export function Teams({ teams }: { teams: Record<string, unknown>[] }) {
  const [sortKey, setSortKey] = useState('load');
  const [sortOrder, setSortOrder] = useState<'asc' | 'desc'>('desc');
  const sort = (key: string) => {
    setSortOrder(key === sortKey && sortOrder === 'asc' ? 'desc' : 'asc');
    setSortKey(key);
  };
  return (
    <SpTable
      caption="On-call teams"
      columns={columns}
      data={uiSortRows(teams, sortKey, sortOrder)} // the table draws rows as given
      rowKey="team"
      sortKey={sortKey}
      sortOrder={sortOrder}
      onSort={sort}
      striped
    />
  );
}

import { Component, computed, input, signal } from '@angular/core';
import { uiSortRows } from '@silverpoint/core/ui';
import { SpTable } from '@silverpoint/angular/ui/table';

@Component({
  selector: 'app-teams',
  imports: [SpTable],
  template: `
    <sp-table caption="On-call teams" [columns]="columns" [data]="rows()" rowKey="team"
      [sortKey]="sortKey()" [sortOrder]="sortOrder()" [striped]="true" (sort)="sort($event)" />
  `,
})
export class Teams {
  readonly teams = input.required<Record<string, unknown>[]>();
  protected readonly columns = [
    { key: 'team', title: 'Team', sortable: true },
    { key: 'region', title: 'Region' },
    { key: 'load', title: 'Load %', align: 'end', sortable: true },
    { key: 'incidents', title: 'Incidents', align: 'end', sortable: true },
  ] as const;
  protected readonly sortKey = signal('load');
  protected readonly sortOrder = signal<'asc' | 'desc'>('desc');
  protected readonly rows = computed(() => uiSortRows(this.teams(), this.sortKey(), this.sortOrder()));

  protected sort(key: string) {
    this.sortOrder.set(key === this.sortKey() && this.sortOrder() === 'asc' ? 'desc' : 'asc');
    this.sortKey.set(key);
  }
}
python
class State(rx.State):
    rows: list[dict] = TEAMS
    sort_key: str = "load"
    sort_order: str = "desc"

    @rx.event
    def sort(self, key: str):
        same = key == self.sort_key and self.sort_order == "asc"
        self.sort_key, self.sort_order = key, "desc" if same else "asc"
        self.rows = sort_rows(TEAMS, self.sort_key, self.sort_order)

    Surface props

    In React, Vue and Angular every component takes ground, substrate, mode, size, palette and id, and reads them from the provider. A value binds as each framework does it (value + onChange, v-model, [(value)] or a forms directive), and an overlay's open state with open + onOpenChange, v-model:open or [(open)] (or defaultOpen).

    In Reflex every builder takes ground, substrate, mode, size (sm, md, lg), seed, palette, id, class_name and style. Values and lists (rows, items, options) can be static or state vars. Value components (sp_textarea, sp_input_number, sp_select, sp_pagination) send the new value itself to on_change, never a DOM event. Overlays are controlled with open + on_open_change, or uncontrolled with default_open.
