Slide decks

New in silverpoint 0.9 and reflex-silverpoint-react 0.9. SpDeck draws a Marp/Marpit Markdown presentation in silverpoint: the silverpoint theme on the library's grounds and substrates, directives that move a slide to another ground or to precision, fragments, presenter notes, and silverpoint fences that become real charts inside a slide.

Try it

A Marp deck drawn by sp_deck. Click into it, then use the arrows, Space, PageUp/PageDown or Home/End; o opens the overview, f full screen and n the notes. Each list item is a fragment, revealed a step at a time; each chart is a silverpoint fence, hydrated in place. The controls set the deck's props; a slide's own directive wins.

Install

In React, Vue and Angular, SpDeck is on the deck subpath of the adapter, and its engine, @silverpoint/marp (which brings @marp-team/marpit), is an optional peer: install it only for decks. Import four stylesheets, in this order (Angular lists them in the styles array of angular.json):

ts
import '@silverpoint/fonts/fonts.css';
import '@silverpoint/grounds/styles.css';
import '@silverpoint/grounds/ui.css';
import '@silverpoint/marp/deck.css';

In Reflex, sp_deck (reflex-silverpoint-react 0.9.0 or later) lists @silverpoint/marp as its own npm dependency and imports the four stylesheets, so an app installs the engine only when a page renders a deck. MARP_VERSION and DECK_STYLESHEETS say which.

In your code

shell
npm install @silverpoint/react @silverpoint/marp @silverpoint/grounds @silverpoint/fonts
tsx
// src/main.tsx: the stylesheets, in this order
import '@silverpoint/fonts/fonts.css';
import '@silverpoint/grounds/styles.css';
import '@silverpoint/grounds/ui.css';
import '@silverpoint/marp/deck.css';

// src/Talk.tsx
import { useState } from 'react';
import { SpDeck } from '@silverpoint/react/deck';
import markdown from './talk.md?raw';

export function Talk() {
  const [page, setPage] = useState(1);
  return (
    <SpDeck
      markdown={markdown}
      page={page}
      onPageChange={({ page }) => setPage(page)}
      onReady={({ total }) => console.log(total, 'slides')}
      showNotes
    />
  );
}

// angular.json → "styles": [
//   "@silverpoint/fonts/fonts.css", "@silverpoint/grounds/styles.css",

// src/app/talk.ts

shell
pip install 'reflex-silverpoint-react>=0.9.1'
python
from pathlib import Path

import reflex as rx
from reflex_silverpoint_react import sp_deck  # installs @silverpoint/marp as the deck's npm dependency

TALK = Path("assets/decks/talk.md").read_text()  # read when the app compiles


class Deck(rx.State):
    page: int = 1
    total: int = 0

    @rx.event
    def on_page_change(self, page: int, total: int):
        self.page, self.total = page, total

    @rx.event
    def on_ready(self, total: int):
        self.total = total


def talk() -> rx.Component:
    return sp_deck(
        TALK,
        page=Deck.page,  # controlled; or default_page=1
        on_page_change=Deck.on_page_change,  # (page, total)
        on_ready=Deck.on_ready,  # (total,)
        show_notes=True,
        palette="iron_gall",  # a preset's name, either spelling
        id="talk",
    )

Writing a deck

Slides are separated by ---. The front matter sets the deck's directives; a <!-- key: value --> comment sets one from that slide on, and <!-- _key: value --> on that slide only. Any other comment is a presenter note, and each list item a fragment.

markdown
---
paginate: true
header: My talk
ground: silverpoint
substrate: cream
---

<!-- _class: lead -->

# Title slide

---

<!-- _ground: cyanotype -->

## A chart on cyanotype

```silverpoint
{"chart": "bar-chart", "props": {"title": "Visits"}, "height": 400}
```

<!-- A presenter note: any comment that is not a directive. -->

---

* fragment one
* fragment two

The silverpoint theme's classes, set with <!-- _class: lead -->:

ClassEffect
leadA title slide: the content centred, the heading larger, one rule under it.
invertLight text on the substrate darkened to the ground's ink; its contrast computed per ground.
plateAn inked plate mark, a double rule inset from the edge, behind the content.
hatchedAn inked hatched band around the slide, behind the content.
Note
Raw HTML is never rendered: it shows as text, and javascript: and non-image data: URLs are dropped. A <style scoped> block still restyles one slide, and Marpit's background images (bg, split backgrounds such as bg right:40%, sizing and filters) keep their meaning.

Charts in a slide: the silverpoint fence

A fenced block whose language is silverpoint holds one chart as JSON, the same input as the MCP render_chart tool. It is static SVG in the server's render and a live chart in the browser (unless interactive is false), and it takes its slide's ground, substrate and mode unless it names its own.

markdown
```silverpoint
{"chart": "bar-chart", "props": {"title": "Visits by quarter"}, "height": 400}
```

propsthe chart's own props, camelCase (not the fence's fields){}
datathe rows the chart readsits demo dataset
width160 .. 1280 canvas pxthe slide's content width
height90 .. 720 canvas px360
idthe chart's id<deck>-s<slide>-c<ordinal>
ground · substrate · mode · paletteas on any chartthe slide's
DiagnosticWhen
SP026A fence that is not JSON, names an unknown chart or prop, or asks for a size out of range: an error figure in its place.
SP027An unknown directive value, or a substrate of another ground: the inherited value is kept.
SP029A deck past a limit (512 KB, 300 slides, 60 fences): it renders up to the limit.

Server rendering and print

The server sends the current slide, its static charts and the controls; the browser adopts that markup, adds the controller and hydrates the charts, with no mismatch. In Next.js SpDeck renders in the App Router (a component that holds the page in state needs 'use client'); Vue renders it with @vue/server-renderer and Angular with @angular/ssr. This page is a static export: its deck was rendered when the site was built.

Printing lays every slide out at its own size, every fragment shown and the controls hidden.

Without a framework, the engine is pure: the same Markdown, options and id give the same render on the server and in the browser.

ts
import { createDeckEngine } from '@silverpoint/marp';

const deck = createDeckEngine({ id: 'talk', ground: 'silverpoint' }).render(markdown);
deck.slides;      // per slide: its HTML, notes, fragment count, ground, substrate, mode, classes
deck.css;         // the theme, scoped to the deck's id
deck.diagnostics; // SP026, SP027, SP029, … with their slide

Marp CLI and VS Code

@silverpoint/marp/theme.css carries both grounds as a plain Marp theme. There, backdrops (plate, hatched) draw no ink, a fence is shown as code and there is no controller; with silverpoint's own engine, Marp CLI draws the directives, the backdrops and the fences as static SVG.

shell
# Marp CLI with the plain theme (fences shown as code, no controller)
npx @marp-team/marp-cli --theme node_modules/@silverpoint/marp/theme.css talk.md

# Marp CLI with silverpoint's engine (directives, backdrops and fences as static SVG)
npx @marp-team/marp-cli --engine @silverpoint/marp/cli talk.md

# VS Code: the Marp extension's settings.json
"markdown.marp.themes": ["./node_modules/@silverpoint/marp/theme.css"]

Decks and agents

The silverpoint MCP server checks a deck with validate_deck (its slide count and every diagnostic), renders it as a standalone HTML document with render_deck, and writes the deck's code (SpDeck, or sp_deck in Reflex) with generate_code and a deck target.
